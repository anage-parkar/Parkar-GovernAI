AI Gateway — Setup & Usage Guide

How to route every LLM and agent-tool call through Parkar GovernAI — from adding a provider key to seeing governed traffic, cost, and audit logs. This guide follows the exact order you set things up in.

What the gateway does

The AI Gateway is a single governed endpoint your apps and agents send traffic to instead of calling model providers directly. On every call it enforces policy, runs guardrails (PII / content filters), tracks spend and rate limits, and logs the full request — so you get control and an audit trail without changing how your app is built.

LLM traffic

OpenAI-compatible /v1/chat/completions endpoint, authenticated with a virtual key. Works with any OpenAI-style SDK.

Tool / MCP traffic

Streamable-HTTP /v1/mcp endpoint, authenticated with an agent key. Proxies and audits every tool call.

The end-to-end flow

Set things up in this order. Steps 1–6 govern model calls; steps 7–9 govern tool calls.

Provider API key→ Endpoint (slug)→ Virtual key (sk-vw-…)→ Connect app→ Guardrails
MCP server→ Discover tools→ Agent key (sk-mcp-…)→ Connect agent→ Logs & metrics

Prerequisites

  • The stack running (frontend on :5173, gateway reachable on :8100).
  • Logged in as an org Admin (the AI Gateway config requires the Admin role).
  • A provider API key to govern (OpenAI / Anthropic / Gemini / Mistral / xAI / OpenRouter).
Where you do this Everything below is under AI Gateway in the left module switcher. The UI calls the backend, which proxies to the gateway — you don't touch the gateway directly.
1

Add a provider API key

Store the upstream provider credential the gateway will use to actually call the model. It's encrypted at rest (AES-256) and never shown again.

UI: AI Gateway → Settings → API keys → Add API key.

FieldExampleNotes
Key nameAnthropic-ProdA label for your reference.
ProvideranthropicOne of: openai, anthropic, gemini, xai, mistral, openrouter.
API keysk-ant-…Your real provider key. Stored encrypted.
Encryption key matters The provider key is encrypted with the backend's ENCRYPTION_KEY. If that env value changes later, previously-saved keys become unreadable — set it once and re-save keys only if you rotate it.
2

Create an endpoint

An endpoint binds a provider + model + your API key under a short slug. The slug is what your app sends as the model field — clients never see the real model name or key.

UI: AI Gateway → Endpoints → Create endpoint.

FieldExampleNotes
Slugclaude-sonnetLowercase, hyphens. This is the "model" clients call.
Display nameClaude SonnetFor the UI.
ProvideranthropicMust match the API key's provider.
Modelanthropic/claude-sonnet-4-6LiteLLM format — see the warning below.
API keyAnthropic-ProdThe key from step 1.
Model name format — the #1 mistake The model must be in LiteLLM provider/model form:
  • Anthropic → anthropic/claude-sonnet-4-6
  • Gemini → gemini/gemini-2.5-flash (note the gemini/ prefix — a bare gemini-… or a doubled gemini/gemini/… will fail)
  • OpenAI → gpt-4o or openai/gpt-4o
3

Create a virtual key

A virtual key (sk-vw-…) is the credential your app authenticates with. It's decoupled from the provider key — you can revoke it, scope it, budget it, and rate-limit it independently. One key per app/client/agent is the clean pattern.

UI: AI Gateway → Virtual keys → Create key.

FieldExampleNotes
NameAIONIQ Agent KeyLabel.
Allowed endpointsclaude-sonnet, gemini-apiWhich endpoints this key may call.
Monthly budget (USD)50Optional cap; calls return 402 when exceeded.
Rate limit (RPM)60Optional; calls return 429 when exceeded.
Copy it now The full sk-vw-… value is shown only once at creation. Store it where your app reads its config.
4

Connect your app

Point your app at the gateway's OpenAI-compatible URL, use the virtual key, and set model to your endpoint slug. That's the whole change — no provider SDK swap needed.

OpenAI SDK (Python)

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8100/v1",     # the gateway
    api_key="sk-vw-…",                        # your virtual key
)
resp = client.chat.completions.create(
    model="claude-sonnet",                    # the endpoint SLUG, not the real model
    messages=[{"role": "user", "content": "Hello"}],
    extra_headers={"x-vw-metadata": '{"app":"aioniq","user":"alice@acme.com"}'},
)
print(resp.choices[0].message.content)

LangChain

from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    base_url="http://localhost:8100/v1",
    api_key="sk-vw-…",
    model="claude-sonnet",                    # endpoint slug
    default_headers={"x-vw-metadata": '{"app":"aioniq","user":"alice@acme.com"}'},
)

Google ADK (LiteLlm)

from google.adk.models.lite_llm import LiteLlm

model = LiteLlm(
    model="openai/claude-sonnet",             # openai/ + endpoint slug
    api_base="http://localhost:8100/v1",
    api_key="sk-vw-…",
    extra_headers={"x-vw-metadata": '{"app":"aioniq","user":"alice@acme.com"}'},
)
Anthropic via the OpenAI shape Even though the model is Claude, your client talks OpenAI wire format to the gateway — the gateway translates to the real provider. So use an OpenAI-style client (or LiteLLM's openai/ prefix), not the native Anthropic SDK.
5

Add guardrails

Guardrails inspect each request before it reaches the model and can block or mask. This is where governance becomes active, not just observational.

UI: AI Gateway → Guardrails → create a rule.

TypeConfigAction
content_filterkeyword or regex (e.g. block nightfall)block
piientity types (EMAIL, SSN, …)mask or block

When a request is blocked, the gateway returns HTTP 400 with a reason, and a row is written to the guardrail log. Example block message:

400 — {"detail": "Request blocked by guardrail: content_filter: <rule> detected"}

View blocks under Logs → Guardrails tab, and aggregate counts on the dashboard.

6

Budgets & rate limits

Set these per virtual key (step 3) or per endpoint. They enforce automatically:

  • Budget exceeded → request rejected with 402.
  • Rate limit exceeded → request rejected with 429.

Both rejections are logged and surface as counters on the dashboard (capacity / upsell signal). Budgets reset monthly.

7

Register an MCP server

To govern an agent's tools, the gateway proxies to upstream MCP servers. The gateway doesn't host tools itself — you register a server that exposes them over Streamable HTTP.

UI: AI Gateway → MCP → Servers → add a server.

FieldExample
Name / slugAIONIQ Tools / aioniq-tools
URLhttp://host.docker.internal:3001/mcp if gateway is in Docker and server on host
Auth typenone / bearer / api_key

Then click Discover on the server — the gateway calls tools/list and imports each tool (e.g. web_search, calculator).

The server must speak Streamable HTTP An npx/stdio-only MCP server can't be registered directly — host it over HTTP (e.g. a small FastMCP server: mcp.run(transport="streamable-http")) and the gateway proxies to its URL.
8

Create an agent key

An agent key (sk-mcp-…) is what your agent uses to reach the MCP gateway. Like virtual keys, you can scope it (allowed tools / servers) and rate-limit it.

UI: AI Gateway → MCP → Agent keys → create. Copy the sk-mcp-… (shown once).

9

Connect your agent's tools

Point your agent's MCP client at the gateway's /v1/mcp endpoint with the agent key. Every tools/call is then proxied and audited.

Google ADK

from google.adk.tools.mcp_tool.mcp_toolset import (
    MCPToolset, StreamableHTTPConnectionParams,
)

toolset = MCPToolset(
    connection_params=StreamableHTTPConnectionParams(
        url="http://localhost:8100/v1/mcp",
        headers={"Authorization": "Bearer sk-mcp-…"},
    )
)
# pass tools=[toolset] to your Agent(...)

LangChain / LangGraph

from langchain_mcp_adapters.client import MultiServerMCPClient

client = MultiServerMCPClient({
    "parkar": {
        "transport": "streamable_http",
        "url": "http://localhost:8100/v1/mcp",
        "headers": {"Authorization": "Bearer sk-mcp-…"},
    }
})
tools = await client.get_tools()   # feed into your agent
Tools the LLM can use must reach the LLM The model only calls a tool if the tool definitions are sent in the LLM request. When routing through the gateway, ensure your endpoint/model supports tool-calling and the request includes tools. Local LangChain @tool functions that run in-process are not seen by the gateway — expose them via MCP to govern/audit them.

Logs, metrics & insights

Once traffic flows, everything is visible under AI Gateway:

WhereWhat you see
LogsPer request: provider, model, tokens, cost, latency, status, metadata tags. Expand a row for the prompt & response (system prompts hidden) and the requester.
Logs → GuardrailsEvery block/mask event, by type.
DashboardTotal cost / requests / tokens, avg & P95 latency, error rate, cache hit rate.
Dashboard → Operational insightsCost per client/agent, budget utilization + alerts, 429/402 counts, PII detections by type, per-agent tool latency & blocks, spend anomaly flag.
MCP → AuditEvery tool call: by tool, by agent, success/error/blocked, latency.

Tracking the requester (per-user)

The gateway authenticates a key, not a person — so attach the end-user's identity per request via the x-vw-metadata header:

x-vw-metadata: {"app":"aioniq","agent":"sales-bot","user":"alice@acme.com"}
  • The user (and any tags) appear on each Logs row.
  • Break down spend by anyone: Dashboard → cost-by-tag, e.g. tag=user or tag=app.
Trust note Tags are asserted by your app, not enforced by the gateway — perfect for tracking/chargeback. For per-user enforcement (budgets/blocking per person), issue one virtual key per user instead.

Gotchas & troubleshooting

SymptomCause & fix
404 model not found from providerWrong model name on the endpoint. Use exact provider model IDs in LiteLLM form (e.g. anthropic/claude-sonnet-4-6, gemini/gemini-2.5-flash).
Agent "has no tools"Tool defs didn't reach the LLM, or the MCP toolset failed to connect. Check the agent key, the /v1/mcp URL, and that the MCP server is running & discovered.
402 on every callVirtual-key or org budget exhausted. Raise the budget or wait for monthly reset.
429 burstsRate limit hit — raise rate_limit_rpm on the key/endpoint.
Request blocked (400)A guardrail matched. Check Logs → Guardrails for the rule and matched text.
Cost shows $NaN / 0Model not in the cost DB (cost falls back to 0) — calls still work; pick a known model for accurate costing.
Empty Gemini replyThinking models can consume a low max_tokens before emitting text — raise max_tokens.
